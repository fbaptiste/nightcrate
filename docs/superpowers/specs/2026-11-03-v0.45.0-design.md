# v0.45.0 — Common names for galaxies and nebulae

**Status:** written 2026-11-03. Fred chose to skip the spec questions
("skip questions and proceed"), so every decision below not quoted from him
is Claude's call, listed at the end for his review with the plan.

## Why

Many popular imaging targets can't be found by name, because NightCrate has
no name for them. On Fred's database (2026-11-03), 171 of 45,436 objects
have a common name: 49 of 33,495 galaxies and 20 of 370 HII regions. NGC 891,
NGC 3628 (Hamburger Galaxy), IC 342 (Hidden Galaxy), NGC 5907 (Splinter
Galaxy), NGC 4656 (Hockey Stick), Sh2-129 (Flying Bat), Sh2-132 (Lion),
LBN 437 (Gecko), LBN 777 (Vulture Head) and IC 1795 (Fish Head) have none.

Where a name exists, it shows badly: an object's names are one
comma-separated text field, shown as is everywhere ("Barbell Nebula,Cork
Nebula,Little Dumbbell Nebula" for M 76, including plate-solve labels),
and its first name is whatever the source catalog lists first.

## Goals

1. **Find a target by any of its names.** Every name NightCrate knows for an
   object is searchable wherever designations are: the catalog, the
   planner, the wishlist and project target search.
2. **Show one name, the one imagers use.** Each object shows one preferred
   name in lists, cards, labels and sorting. The others appear in the detail
   panels ("Also known as …").
3. **A reviewed list of names.** NightCrate ships its own list of names,
   checked against independent sources, covering the deep-sky objects
   imagers target that lack a name today or carry the wrong one first.

## Non-goals

- Names for stars, double stars or asterisms beyond what the catalogs give.
- Names in languages other than English.
- User-entered or user-edited names.
- Fetching names from any site at runtime.
- A naming authority: NightCrate records names in established use and
  invents none.

## Anti-goals (what would make this a failure even if it works)

- A wrong name on an object, such as Wikidata's "Squid Nebula" on Sh2-129.
  It belongs to Ou 4, a separate object inside it. A missing name is better
  than a wrong one.
- Copying another site's compiled list, which copies their work rather than
  stating facts.
- A slower catalog or planner. Searches may cost at most 10% or 20 ms more
  than before, whichever is larger, measured on a full catalog (Claude's
  call).

## Decisions

### Data model (Claude's call)

- `dso.common_name` holds **only the preferred name**: no commas, used by
  every existing list, card, label, sort and the Google search link.
- **New table `dso_other_name`**: `(id, dso_id → dso ON DELETE CASCADE,
  name, position)`, unique on `(dso_id, name)` case-insensitively, in
  display order. It is catalog-derived: it never keeps an object alive the
  way a project or wishlist link does.
- **Group names:** `dso_group` gains a nullable `common_name`, for named
  groups with no single object of their own (Arp 244, the Antennae
  Galaxies; Arp 242, the Mice).
- Migration 0067 adds both; no existing column changes.
- **Why a table, not the comma string:** the project keeps data normalized,
  a separator inside a text field breaks on the first name that contains
  one, and the other names need their own place in the UI and the search.

### Where names come from (Claude's call, revised after Codex's plan review)

- **Every catalog name is kept.** An object's names are the names of its
  catalog entry and of every entry merged into it (rule R, the Sharpless
  and Barnard cross-references), split on commas, trimmed, and
  de-duplicated case-insensitively, in collector order. Today a merged
  entry's names are dropped.
- **NightCrate's list adds and orders.** For a listed object, the list's
  names come first in the list's order (its rank 1 is the preferred name),
  followed by the catalog names it doesn't repeat. A list row can also
  **remove** a catalog name that is wrong for that object, with its
  evidence. `common_name_augmented` is 1 exactly for listed objects.
- **One reviewed source of names.** The augment file's
  `common_name_override` column (56 rows) moves into the new list. Those
  names are verified like any other first. The augment file keeps surface
  brightness and distances.
- **No runtime Wikidata names.** Wikidata (CC0) is used only to check and
  find names while building the list; its errors (Sh2-129 above) rule out
  importing it.
- **Names aren't globally unique.** An object kept inactive for a user link
  keeps its names, so the database can't forbid two objects sharing one.
  The shipped list never gives one name to two objects. A full-catalog
  audit lists names shared by two active objects for review.

### The reviewed list (Claude's call)

- **File:** `backend/src/nightcrate/data/catalogs/nightcrate/common_names.csv`,
  GPL-3.0-or-later like the rest of NightCrate (Fred, 2026-11-03). One row
  per name:
  `designation,target,name,action,rank,sources,verified,notes`.
  - `target` is `object` or `group`. A group row names a group by its
    designation and never falls back to an object.
  - `action` is `name` (rank 1..n per object; rank 1 is preferred) or
    `remove` (drops a wrong catalog name; no rank).
  - `sources` holds at least two independent sources as stable identifiers:
    SIMBAD main identifier, NED name, Wikidata QID, or a URL.
  - `verified` is the date checked.
  - A group with no single object (Arp 244) takes one name.
- **Scope:** galaxies, nebulae of every kind (emission, reflection, dark,
  planetary, supernova remnants, cluster-with-nebula), star clusters (Fred,
  2026-11-03), and named galaxy groups. Clusters were first left out on the
  wrong assumption that their names exist already: on Fred's database only
  21 of 668 open clusters and 4 of 208 globular clusters have one (M 35–38,
  M 41, M 2–5, M 15, M 22 and M 92 have none), and M 11 shows the French
  "Amas de l'Ecu de Sobieski" first. Objects in optional catalogs are listed too; their rows
  apply when the catalog is loaded and are skipped quietly otherwise, as
  augment rows are. There is no target count; the list is as long as the
  verified names.
- **Verification:**
  - Claude drafts the names from its own knowledge and marks how sure it is
    of each.
  - Every name must be confirmed for that object by **two independent
    sources** from:
    - SIMBAD's `NAME` identifiers (its Harvard mirror while Strasbourg is
      down);
    - NED;
    - Wikidata labels and aliases, or Wikipedia, which count as one source
      between them;
    - NASA, ESA, ESO, NOIRLab or observatory pages;
    - published catalogs.
  - A name confirmed by one source only is left out and listed for Fred.
  - Parts are never named after the whole, nor the whole after a part
    (Sh2-129 / Ou 4).
  - Before acceptance, a full-catalog audit loads every catalog and checks
    that every row resolves. It flags two designations that resolve to one
    object, including through merges, and names shared by two active
    objects.
- **Sources are evidence, not material.** Names are checked one by one, as
  facts; nothing is copied from another site's list. Wikipedia text could
  now be adapted under GPL-3.0 with attribution (CC BY-SA 4.0 → GPLv3), but
  isn't needed: a single name is a fact.

### Search (Claude's call)

The shared search clause (`api/dso.py:dso_search_clause`, used by the
catalog and the planner) also matches other names, case-insensitively by
substring as `common_name` is matched today. It also matches a group's name
and a group whole's other names, returning the members. The
exact-designation lookup is unchanged. Search must not get slower than an
agreed budget, measured before and after on a full catalog.

### Display (Claude's call)

- Every place that shows one name shows the preferred name. Most need no
  change because they read `common_name`.
- **Hover shows the other names wherever a result's name appears** (Fred,
  2026-11-03: the detail panel alone "hides that too much"; someone who
  searched "Cork" and sees "Little Dumbbell Nebula" would be confused).
  Hovering or focusing the name in the catalog table, the planner cards
  (Plan a Night and Full Catalog), the wishlist, the add-target search
  options and the plate-solve object grid shows a tooltip: "Also known as
  Barbell Nebula, Cork Nebula". No underline or icon marks it (UI rule).
  Image overlay labels are left out, where hover would fight pan and zoom.
- The catalog and planner detail panels, and the plate-solve detail, also
  show the other names under the preferred one, as a line.
- The API adds `other_names: list[str]` to the object detail, the catalog
  list items, the planner items, the wishlist items and the plate-solve
  objects. Lists load them only for the rows returned.
- A named group's "Part of" chips and pills show its name after its
  designation ("Part of Arp 244 · Antennae Galaxies"). The catalog list and
  the detail carry the same group reference: designation, whole object and
  name.
- The Google search link uses the preferred name.
- **Not in this version:** showing which other name matched a search.

### Existing databases (Claude's call)

Migration 0067 splits every stored comma string, including those of
inactive objects kept for user links, which no later load rewrites. The new
list file is an object input, so the first eligible load after upgrading
runs the object step once and applies the list (a load deferred by a
missing catalog file waits, as today). No repair check is needed. A second
start must run no object step, the rule from v0.44.0's "repair checks must
settle".

## Constraints

- Migration 0067 adds a table and a nullable column, and splits existing
  names; never edit 0066 or earlier.
- Upgrades are verified on a copy of a database at 0066, as well as a fresh
  one: integrity and foreign keys checked, user links kept.
- NightCrate's own data files are GPL-3.0-or-later. README acknowledges
  SIMBAD, NED and Wikidata as verification sources.
- Retained inactive objects (kept for user links) keep their names.

## Left to the builder

- How `build_object_set` gathers names from merges, within the rules above.
- Exact layout of the "Also known as" line, within the existing panel
  styles.
- Test fixtures.

## Claude's calls, for Fred's review

1. One preferred name on each object, with the others in a new table,
   rather than keeping the comma string.
2. Every catalog name is kept. NightCrate's list adds names, orders them,
   and removes wrong ones with evidence.
3. The augment file's 56 name overrides move into the new list and are
   verified first.
4. Wikidata checks names; it doesn't supply them at runtime.
5. Two independent sources per name, with Wikidata and Wikipedia counted as
   one; single-source names go to Fred.
6. Galaxies, nebulae, star clusters (Fred) and named galaxy groups are in
   scope. There is no target count.
7. Other names show in a hover tooltip on result names (Fred) and as a line
   in the detail panels. A group's name shows on its "Part of" chips.
8. Wikipedia is evidence for single names only; no text or lists are copied.
9. Not in this version: marking which other name matched a search; the
   tooltip shows all of them.
