# v0.45.0 — implementation plan

> **For agentic workers:** Codex implements one task at a time under
> `docs/agent-collaboration.md` §4. Claude builds the names list (Task 0),
> reviews each handoff, re-runs checks and stages. Steps use checkbox syntax.

**Goal:** every name of a deep-sky object is searchable, each object shows
one preferred name with its other names on hover, and NightCrate ships a
reviewed list of verified names for galaxies, nebulae and star clusters.

**Architecture:**
- `dso.common_name` becomes the preferred name only, and the new table
  `dso_other_name` holds the rest; `dso_group` gains a `common_name` for
  named groups.
- The reviewed list `common_names.csv` is an editorial object input, like
  the match overrides. `reconcile.build_object_set` decides every object's
  and group's names in one place: catalog names from the entry and every
  entry merged into it, plus the list's additions, order and removals.
  `apply_object_set` writes them.
- Migration 0067 creates the table and column and splits the existing comma
  strings, inactive objects included.

**Tech stack:** Python 3.14, sqlite3/aiosqlite, yoyo (a Python migration, as
0064), FastAPI/Pydantic, React/MUI (all existing).

**Spec:** [2026-11-03-v0.45.0-design.md](../specs/2026-11-03-v0.45.0-design.md).

**Base:** branch `v0.45.0/common-names` at `868fe7b`, with the licence change
staged (see `PLAN.md`).

**Order:** Task 1, then Task 2 (which delivers the list validator), then
Tasks 3 and 4. Claude drafts and verifies the list (Task 0) alongside them.
Task 0's final acceptance, the full-catalog audit, follows Task 2.

## Global Constraints

- Never edit migrations 0001–0066. Migration 0067 adds `dso_other_name` and
  `dso_group.common_name` and splits existing names.
- `dso_other_name` is catalog-derived: listed in
  `user_links.CATALOG_DERIVED_TABLES`, so it never protects an object from
  removal or merge cleanup.
- NightCrate data files are GPL-3.0-or-later. New files carry the licence
  line "GPL-3.0-or-later (see LICENSE at the repository root)".
- A name never contains a comma, and `dso.common_name` never contains one
  after 0067.
- Within one object, names are unique case-insensitively. Across objects,
  the shipped list never gives one name to two objects. The database allows
  it, because retained inactive objects keep their names.
- **Names are kept, not replaced:**
  - catalog names come from the entry and every entry merged into it;
  - the list adds names, orders them, and removes a name only through an
    explicit `remove` row;
  - `common_name_augmented` is 1 exactly for listed objects and written
    explicitly as 0 otherwise.
- A list row whose designation doesn't resolve because its optional catalog
  is off is skipped quietly (DEBUG). If its catalog is on, it logs a
  warning, as augment rows do.
- **Repair checks must settle:** a second `load_catalogs(force=False)` on
  unchanged inputs runs no object step. Assert this with call counts.
- No unbounded id lists in SQL.
- **Search speed budget:** at most 10% or 20 ms slower than before,
  whichever is larger. Measured on a full catalog, for hits, misses and
  group names, in both the catalog and the planner.
- The list adds no `dso_source_entry` rows: those record which catalogs
  provide an object, and removal relies on them.

## Review Focus

1. **Removing a catalog whose object has only other names left** (no user
   link): the object is deleted, not kept for its names. *Test:* Task 2,
   `test_other_names_do_not_retain_objects`.
2. **A merged entry's names** (a Barnard or Sharpless cross-reference, or a
   rule R merge) are searchable on the owner, and leave when that catalog
   is removed. *Test:* Task 2, `test_merged_entry_names_follow_catalog`.
3. **Two list rows that resolve to one object through different
   designations** ("M 76" and "NGC 650"): the shipped-file audit fails. At
   runtime the first row's designation wins, with a warning. *Test:*
   Task 2, `test_list_conflicting_designations_for_one_object`.
4. **A listed object whose optional catalog is turned on later:** its
   names apply then and leave on removal, and a linked object that is kept
   keeps them. *Test:* Task 2, `test_list_names_follow_optional_catalog`.
5. **Upgrade with a retained inactive object** whose comma name was kept
   for a project link: 0067 splits it, and later loads leave it alone.
   *Test:* Task 1, `test_0067_splits_inactive_retained_names`.

**Interfaces:**
- **Produces:**
  - `split_common_names(text: str | None) -> tuple[str, ...]`: the names in
    order, trimmed, de-duplicated case-insensitively, empty parts dropped.
  - `merge_names(*name_lists: Iterable[str]) -> tuple[str, ...]`: the
    lists concatenated in order, de-duplicated case-insensitively, first
    occurrence kept.
  - `@dataclass(frozen=True, slots=True) class ListedNames: designation:
    str; target: Literal["object", "group"]; names: tuple[str, ...];
    removals: frozenset[str]`. `names` are in rank order and `removals` is
    case-folded.
  - `read_common_names(source: CatalogSource | None) -> list[ListedNames]`.
    It raises `ValueError` for:
    - a bad rank sequence, or a rank on a `remove` row;
    - a comma in a name;
    - fewer than two sources on a `name` row;
    - one name assigned (`action=name`) to two designations, or twice to
      one. Removing a name from one target and assigning it to another is
      valid;
    - an unknown action or target;
    - a `group` target with more than one `name` row, or with a `remove`
      row;
    - an unparsable designation.
  - Registry source `nightcrate_common_names`: parser `"common_names"`,
    `license=NIGHTCRATE_LICENSE`, file `common_names.csv`.
  - `NewObject.other_names: tuple[str, ...] = ()`;
    `NewGroup.common_name: str | None = None`.
  - Object columns `common_name` (preferred, or None) and
    `common_name_augmented` (0 or 1).
- **Name rule per object:**
  - `catalog = merge_names(split(owner entry), split(each merged entry),
    …)`: the owner's names first, then each merged contribution ordered by
    source precedence (the collector order) and then the contributing
    row's original ordinal in its file. Each row keeps its internal name
    order. A deferred OpenNGC duplicate keeps its row ordinal.
  - if listed: `merge_names(list.names, catalog)` minus `list.removals`;
    otherwise `catalog`.
  - The first name is `common_name` and the rest are `other_names`.
  - **Group rows** (`target=group`) resolve only against the finalized
    `NewGroup` keys, after the collector groups (`reconcile.py:880`) and
    the parts groups (`reconcile.py:978`) exist:
    `_designation_key(designation)` gives the group key. An absent group
    is skipped (DEBUG when its catalog is off). A group row never falls
    back to an object: with Arp off, "Arp 244" is owned by one galaxy
    (`test_arp_loader.py:244`), which must not take the group's name.
