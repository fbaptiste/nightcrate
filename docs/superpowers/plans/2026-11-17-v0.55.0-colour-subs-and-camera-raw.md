# v0.55.0 Colour-Camera Subs and Camera Raw Files: Implementation Plan

> **For agentic workers:** in this repository Codex implements this plan in
> the phases below, each phase one handoff, and Claude reviews each phase
> (`docs/agent-collaboration.md`). Steps use checkbox (`- [ ]`) syntax.
> **Never commit:** leave changes unstaged; Claude stages after review, and
> Fred authorises every commit.

**Goal:** colour subs (FITS, XISF and camera raw) show in colour, while
statistics and measurements keep using the recorded samples. Camera raw
files work in project scans and the analyzer, with batch-correctable frame
type and filter.

**Architecture:** one loader (`services/pixel_loader`) returns a
`LoadedImage`: mono, colour or **mosaic**, with the recorded samples, their
units, and (for a mosaic) its colour pattern and where it came from. Pure
functions turn a loaded image into the form a consumer needs:
- display colour (interpolated);
- per-colour samples (real sites only);
- measurement grey (merged blocks, equal weight per colour);
- colour superpixels (thumbnails).

Raw files are read with `rawpy` (pixels, pattern, levels) and `exiv2`
(metadata). Migration 0075 adds typed fields.

**Tech stack:** Python 3.14, FastAPI, numpy and SciPy, `rawpy` 0.28,
`exiv2` 0.19 (python-exiv2), aiosqlite with yoyo SQL migrations, React with TypeScript
and MUI.

**Spec:** `docs/superpowers/specs/2026-11-17-v0.55.0-colour-subs-and-camera-raw-design.md`
(approved by Fred on 2026-11-17). Read it with this plan; where they differ,
the spec wins. Codex's plan review, round 1, is in
`.superpowers/codex/v0.55.0/15-codex-plan-round1.md`; this revision answers
it.

**Order** (Codex, round 1): foundations, then the project workflow Fred
will use most (scan, correct, sessions, thumbnails), then the analyzer and
measurements, then the screens, then packaging.

## Global Constraints

- **No processing:** no white balance, calibration or stacking. Raw files
  are read-only, and no user file is ever written.
- **No statistic or star measurement uses interpolated pixels.**
- **Recorded values stay recoverable:** every statistic is in the file's
  own recorded units (ADU for integer data; the stored value for float
  data), computed from the recorded samples, never by multiplying
  normalised data back.
- **Spatial units:** star sizes and positions are in **sensor pixels**.
  Detection thresholds are converted into working units before detection,
  and results back after it. A position is
  `x_sensor = (x_block + 0.5) * b - 0.5`.
- **Inferred values are marked, never shown as fact:** a frame type
  guessed from names, an estimated capture time, a user's live pattern
  choice, and a missing `ROWORDER` (assumed top-down).
- **Dependencies:**
  - `rawpy>=0.28,<0.29` (MIT; LibRaw under its LGPL-2.1 option, from the
    official wheels, without the GPL demosaic packs);
  - `exiv2>=0.19.2,<0.20` (python-exiv2, GPL-3.0-or-later; it replaced `pyexiv2`, whose Mac build loads a Homebrew library);
  - no other new runtime dependency.
- **Platforms:**
  - the installed app's minimum macOS is **14.0**;
  - source runs keep working on Intel Macs, and on Apple Silicon Macs
    before macOS 14, with raw files off. The reason is exactly "Raw files
    can't be read on this computer".
- **Workers stay numpy-only:** catalog thumbnails, frame quality and the
  solver workers (`CLAUDE.md`).
- **Migrations:** the next number is **0075**, and existing migrations are
  never edited. Adding columns needs no parent-table rebuild.
- **Raw extensions:** `.cr2 .cr3 .nef .nrw .arw .raf .orf .rw2 .pef .dng`.
- **Frame-type keywords:** light(s); dark(s); flat(s); darkflat(s) or
  flatdark(s); bias(es) or offset.
- **UI:** colour-blind-safe colours, and a pixel's filter colour is spelled
  out in text. No question-mark icons. Theme tokens only.

## Review Focus

1. **A three-plane colour FITS that still carries `BAYERPAT`** is colour
   and never converted again. *Task 4.*
2. **Odd width or height, and every crop phase** (offsets 0 and 1 for
   Bayer, 0–5 for X-Trans): no index errors, and a uniform scene gives a
   uniform grey. *Task 3.*
3. **A 14-bit raw in a 16-bit container:** a sample at the white level
   displays at full scale, and statistics report the recorded ADU. *Tasks
   4 and 5.*
4. **A raw file inside a zip archive** opens and scans. *Tasks 5 and 7.*
5. **A raw file without `DateTimeOriginal`:** it falls back to the file's
   time, marked `file_time`, including the archive-entry time inside a
   zip. *Task 7.*

### Task 2: Colour patterns (`services/cfa.py`)

**Files:** create `services/cfa.py`; test `tests/test_cfa.py`.

**Interfaces:**
- `CfaPattern(rows: tuple[str, ...])`: frozen; rows over `RGB`; `.width`,
  `.height`, `.colour_at(y, x)` with wrap-around.
- `PatternSource = Literal["fits_bayerpat", "fits_colortyp", "xisf_cfa", "raw_file", "user_choice"]`.
- `PatternInfo(pattern, source: PatternSource, detail: str, assumptions: tuple[str, ...])`:
  frozen. `assumptions` lists inferred parts, for example
  `("ROWORDER missing; assumed TOP-DOWN",)`.
- `parse_bayer(text: str) -> CfaPattern | None`: only RGGB, GRBG, GBRG and
  BGGR, trimmed, any case.
- `pattern_from_fits(header: Mapping[str, Any], height: int) -> PatternInfo | None`.
- `pattern_from_xisf(cfa: Mapping[str, str] | None) -> PatternInfo | None`.
- `pattern_from_raw(raw_colors_visible: np.ndarray, color_desc: bytes) -> PatternInfo`.

**The FITS rule** (numpy row 0 is the first stored row, displayed at the
top; N.I.N.A. documents `TOP-DOWN` with sensor pattern and offsets, and
Siril's demosaicing applies the same height-aware rule, per round 1). With
`p` from `BAYERPAT` (else `COLORTYP`), `dx = XBAYROFF` and `dy = YBAYROFF`
(0 by default):
- `TOP-DOWN`: `colour(r, c) = p[(r + dy) % ph][(c + dx) % pw]`;
- `BOTTOM-UP`: `colour(r, c) = p[(H - 1 - r + dy) % ph][(c + dx) % pw]`;
- **no `ROWORDER`:** treated as TOP-DOWN, with an assumption recorded;
- **SharpCap with offsets:** its author confirmed that historical versions
  wrote offsets relative to RGGB beside an already-correct `BAYERPAT`. So
  when `SWCREATE` names SharpCap, the offsets are ignored, and that's
  recorded as an assumption.

- [ ] **Step 1: Write the tests.**
  - The cases from round 1:
    - `BAYERPAT=RGGB, XBAYROFF=1` gives `("GR","BG")`;
    - `YBAYROFF=1` gives `("GB","RG")`;
    - BOTTOM-UP with H=4 gives `("GB","RG")`;
    - BOTTOM-UP with H=5 gives `("RG","GB")`.
  - `COLORTYP` is the fallback, and `BAYERPAT` wins when both are present.
  - The SharpCap rule.
  - The missing-`ROWORDER` assumption.
  - XISF Bayer and a 36-letter X-Trans; unsupported letters give None.
  - Raw: `[[0,1],[3,2]]` with `b"RGBG"` gives `("RG","GB")`.

### Task 3: The forms (`services/mosaic.py`)

**Files:** create `services/mosaic.py`; test `tests/test_mosaic.py`.

**Interfaces:**
- `Mosaic(recorded: np.ndarray, normalised: np.ndarray, pattern: PatternInfo)`:
  `recorded` is `(H, W)` in the file's units; `normalised` is float32 in
  [0, 1], for display only.
- `display_rgb(m) -> np.ndarray`: `(3, H, W)` float32, by normalised

    2R/5G/2B for a uniform scene);
  - from `recorded`, as float32.
- `colour_superpixels(m) -> np.ndarray`: `(3, H // b, W // b)`, per-colour
  means of `normalised`.

### Task 8: Frame type from names

**Files:** `services/ingest_classify.py`, `api/ingest.py`; test
`tests/test_frame_type_names.py`.

**Interfaces:**
- `classify_frame(meta, raw_header, *, filename=None, folder_names: Sequence[str] = ()) -> tuple[str, str, FrameTypeBasis | None]`.
  `FrameTypeBasis = Literal["header", "sky", "file_name", "folder_name"]`.
- `folder_names`, nearest first: the folders between the file and the
  bound folder, then inside an archive, then the bound folder's own name
  (an archive's name without its extension).

**The order:**
1. `IMAGETYP` (basis `header`);
2. on-sky evidence (`sky`);
3. the file name's leading token or pair (`file_name`, as today);
4. folder names (`folder_name`).
