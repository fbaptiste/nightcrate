# v0.54.1 — Faster test runs, grid filters and pickers: Implementation Plan

> **For agentic workers:** this repository's workflow
> (`docs/agent-collaboration.md`) applies. Codex implements one phase at a
> time and leaves the work unstaged; Claude reviews, re-runs the checks and
> stages. Nobody commits, pushes or opens a PR during implementation.
> Steps use checkbox (`- [ ]`) syntax.

**Goal:** the backend suite finishes on GitHub's three machines well inside
the job limit; the Equipment grids can't crash on a filter; FITS header
edits stay with their file; and every equipment and software picker lists
owned items first, in a list wide enough to read. Also: Info becomes the
project editor's second tab, the per-folder Target is removed completely
(migration 0074), and a flipped gallery card hides its front's buttons.

**Architecture:**
- Tests share one migrated, seeded template database per worker and copy
  it for each test.
- CI runs only on PRs, on manual runs and on throwaway `ci/**` branches.
- On the frontend, two small pure helpers decide grid dropdown columns and
  owned-first option lists, so the components only wire them in.

**Tech stack:** Python 3.14, pytest 9, pytest-xdist 3.8, yoyo, aiosqlite;
React 19, TypeScript, MUI 7.3.9, MUI X Data Grid 8.28.1, React Router 7.18.4;
GitHub Actions.

**Spec:** [2026-11-15-v0.54.1-faster-tests-and-grid-filters-design.md](../specs/2026-11-15-v0.54.1-faster-tests-and-grid-filters-design.md)

**Base:** `main` at `36738e7` (v0.54.0 merged), branch
`v0.54.1/faster-tests-and-grid-filters`.

## Global Constraints

- `CLAUDE.md` applies throughout. In particular:
  - read `app_config.APP_DIR` at call time; `tests/test_app_dir_isolation.py`
    enforces this;
  - no new dependencies;
  - MUI `sx`/`styled` only;
  - JSX Unicode needs expressions, not quoted attributes;
  - colorblind-safe colors and theme tokens.
- The same tests must pass and skip as on the base: **4,280 passed and 4
  skipped** on Fred's Mac. Any new test adds to "passed"; nothing that
  passes today may skip or be deleted. **The one exception** is tests of the
  removed per-folder target (A6). Each phase report lists those tests
  removed or changed, with the resulting count delta.
- Nothing may write under the real app-data folder
  (`platformdirs.user_data_dir("NightCrate")`) during a test run.
- The template is copied with `shutil.copyfile`. A hard link would be
  refused by `initialize_workspace` (`db/workspace_upgrade.py:318-335`).
- In Phase A, production code changes only in A6 (the target removal and
  migration 0074) and A7 (scan progress). A1–A5 stay in `tests/`,
  `.github/workflows/checks.yml` and the workflow documents.
- The group labels are exactly **"My Equipment"** (existing) and
  **"My Software"** (new).
- The "Processed with" list width is **`max-content`, at least 280 px and
  at most 420 px**, opening from the field's left edge
  (`placement: "bottom-start"`).
- Required check names are exactly **`checks (macos-15)`,
  `checks (ubuntu-22.04)` and `checks (windows-2022)`**. The matrix job
  name must not change.

## Review Focus

1. **A test that monkeypatches something before `_test_db` runs** and
   expects the database built under that patch would now get the template
   built earlier. The agent survey found none, but the reviewer should
   grep fixtures that run before `_test_db` (autouse fixtures in test
   modules, `pytestmark` usefixtures). A full-suite run with identical
   counts is the check.
2. **A filter value missing from the new options.** Example: "Manufacturer
   is ZWO", then Owned shows only Celestron gear. The grid must not crash
   and simply shows no rows. Pinned by B2's rendered check.
3. **A multi-select software picker with owned items appearing twice**
   ("My Software" plus their category). The selected chips must not
   duplicate, and removing a chip removes the item once. Pinned in B6.
4. **Switching FITS files with unsaved header edits.** The edits must
   neither appear on, nor be saved to, the new file. Pinned in B3's
   rendered check.
5. **Migration 0074 on a real workspace.** It rebuilds `sub_frame`, the
   largest table, which other tables reference. Nothing outside the dropped
   columns may change: child rows, indexes, triggers, the other views and
   the autoincrement counters. Pinned by A6's migration test and Claude's
   check on a copy of Fred's database.
6. **A scan already running when the Files tab opens,** for example after
   switching tabs, or one started by another window. The panel must show it
   and must not start a second scan. Pinned by B10 Step 4.
7. **A crash in an always-mounted page** (image analyzer, gallery, planner,
   DSO catalog and others rendered by `AppShell`, not by a route element).
   It must show the error panel inside the shell, not replace the app.
   Pinned in B4.

### Task A7: Scan progress (backend)

**Files:**
- Create: `backend/src/nightcrate/services/ingest_progress.py`
- Create: `backend/tests/test_ingest_progress.py`
- Modify: `backend/src/nightcrate/api/ingest.py` (`start_ingest`,

  endpoint)
- Modify: `backend/src/nightcrate/services/ingest_models.py` (the response
  model)

**Interfaces:**
- Produces:
  - `ingest_progress.start(workspace: str, project_id: int, run_id: int) -> str`.
    It returns a new `scan_id` (`uuid4().hex`), unique across workspaces and
    restarts. `workspace` is `nightcrate.db.session.workspace_key()`, a
    token that changes on every workspace activation (`db/session.py:65-77`);
    the API passes it in, so the service stays free of database imports;
  - `ingest_progress.folder(folder: str) -> None`. It **resets** `done`,
    `total` and `recent`, so earlier paths never carry the next folder's
    label;
  - `ingest_progress.stage(stage: Literal["listing", "reading", "saving", "grouping"]) -> None`;
  - `ingest_progress.total(n: int) -> None`;
  - `ingest_progress.file_read(path: str, ok: bool) -> None`;
  - `ingest_progress.finish(result: IngestStatus) -> None`. It moves the
    active record into a **per-project** table of finished records, one per
    project, each kept for `RETAIN_FINISHED_S = 300` seconds, like
    `catalog_progress`, and pruned on access;
  - `ingest_progress.snapshot(workspace: str, project_id: int) -> dict | None`.
    It returns that project's running scan, else its last finished scan
    within the retention period, else `None`. Both are keyed by
    **(workspace, project_id)**. Activation swaps the database without a
    restart, so a project id can mean another project afterwards.

  It is in-memory and module-level, with no database or FastAPI imports,
  like `services/catalog_progress.py`: **one active scan** (ingest's single
  flight) plus the per-project finished records, so project A's result
  survives project B starting.
  - `recent` is a `deque(maxlen=10)` of `{path, ok}`, oldest first.
  - `path` is shown relative to the scanned folder using
    `services/ingest_sessions.folder_prefix(folder)`, which handles plain
    folders, archive roots and `::` entries. A path outside the prefix is
    shown whole.
  - `done` counts files read in the current folder; `total` is that
    folder's header-bearing files.
- `GET /api/projects/{project_id}/ingest/progress` →
  `IngestProgress | None`, with fields:
  - `scan_id`, `run_id`;
  - `running: bool`;
  - `folder`, `stage`, `done`, `total`;
  - `recent: list[{path, ok}]`;
  - `result: IngestStatus | None`, set once finished.

  It is read-only. It needs no `admit_work` gate: Codex checked that
  ingest admission and `_INGEST_LOCK` already signal activity to the
  install reservation.
