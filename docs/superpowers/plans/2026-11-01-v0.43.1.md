# v0.43.1 — implementation plan

> **For agentic workers:** Codex implements one phase at a time under
> `docs/agent-collaboration.md` §4. Claude reviews, re-runs checks and stages.
> Steps use checkbox syntax.

**Goal:**
- build the catalog and planner sky images from HiPS tiles, from CDS or ESA;
- download the star file in four parallel pieces;
- stop already-built ranges showing as building;
- keep nebula knots out of the solver's brightest detections.

**Architecture:**
- A new pure-plus-fetch service, `services/hips_tiles.py`, replaces
  `hips_client.py`. The two image caches keep their keys, files and API.
- `http_client.stream_to_file` learns byte ranges. The star download runs
  four piece tasks and assembles them.
- `start_build` filters built ranges, and `/status` checks `built` first.
- Extraction gains a relative width cut before selection.

**Tech stack:** Python 3.14, FastAPI, Pydantic, aiosqlite, numpy, astropy,
astropy-healpix, Pillow, httpx (all existing); React, TypeScript and MUI for
one text line.

**Spec:** [2026-11-01-v0.43.1-design.md](../specs/2026-11-01-v0.43.1-design.md).
**Base:** branch `v0.43.1/sky-tiles-and-downloads`, HEAD `e9e7bf2`. The index
holds the reviewed VizieR fix and PLAN.md.

## Global constraints

- **No new dependencies, no migration, no settings field.** Never edit an
  existing migration.
- **Layering:**
  - services do not import `api/` or FastAPI;
  - read `app_config.APP_DIR` at call time;
  - outbound HTTP goes through `services/http_client.py`.
- **Thumbnails and image rendering are numpy-only:** no GPU and no process
  pool. CPU work runs in `asyncio.to_thread`.
- **The solver's acceptance thresholds, budgets and minimum detection counts
  are unchanged.** The configuration pin test changes only for the new field.
- **Test data:** in-memory synthetic data plus small recorded fixtures (a few
  KB). Real images stay local. Tests never touch the network.
- **Codex never stages, commits or pushes.**
  - Fred's `make dev` (8000, `--reload`) runs from this checkout, and every
    phase must leave it working.
  - Name the test modules to run. Never run the whole suite or GPU tests.
- **Keep comments and naming like the surrounding code.** No new
  question-mark icons. UI copy exactly as written here.

## Review focus

1. **Image orientation.** No mirrored or rotated sky cells or thumbnails at
   any declination, including the poles and RA 0/360 (A1 orientation test,
   live check).
2. **No upstream storm during an outage.** At most 8 tile requests at once,
   and one connect timeout per source per 10 minutes (A1).
3. **Cached images stay valid.** No sweep of the 2,941 existing cells, and
   unchanged filenames and keys (A2).
4. **Star download resume.** Pieces are resumed exactly, with no gap,
   overlap or wrong offset. The SHA-256 still guards the result (B2).
5. **Zero wrong solves** on the corpus and trials (C).

    `down until`) with exactly one probe from `unknown`; while it runs,
    others skip the source, or await it when no other source is usable;
  - mark a source down on a connect error, connect timeout or read timeout;
  - fail at once with no request when every source is down and unexpired;
  - every probe settles (spec §1.3, round 3): success or an HTTP or body

    `unknown`;

  - per-tile shared tasks awaited through `asyncio.shield`;
  - an LRU of `(bytes, source)`;
  - state changes only on the event loop.
- [ ] **`render(wcs, width, height) -> RenderedImage(jpeg, sources)`:**

    2. plan in a thread, storing compact `int32` and `float32` arrays;
    3. fetch the tiles concurrently;
    4. decode, sample and encode in a thread;
    5. release the permit;

  - hold the permit until a started thread has finished, even when the
    caller is cancelled (the shield-and-wait pattern of
    `star_catalog.fetch._in_thread`);

### Task B2: four-piece download

- [ ] **`http_client.stream_to_file`** gains keyword-only `offset: int = 0`
  and `total_size: int | None = None`. `expected_size` stays the length of
  this file.
  - The range is `bytes={offset+have}-{offset+expected_size-1}`.
  - A 206 must carry exactly
    `bytes {offset+have}-{offset+expected_size-1}/{total_size or expected_size}`.
  - A 200 is accepted only when `offset == 0 and allow_whole_file`.
    `allow_whole_file` is a new keyword, default True for the single stream.
    Otherwise it raises the new `RangeNotHonoured(RuntimeError)`, with no
    retry.
  - Everything else is unchanged: one transient retry, `ShortTransfer`, cancel,
    ENOSPC. `MalformedRange` remains for the single stream only; in piece mode
    (`allow_whole_file=False`) a wrong Content-Range raises `RangeNotHonoured`
    before any byte is written.
- [ ] **`star_catalog/fetch.py`:**
  - `PIECES = 4`;
  - `piece_bounds(size, pieces) -> list[tuple[int, int]]`;
  - `piece_path(i)`, the staging file `<compressed>.part{i+1}of4`.
- [ ] **`_download`**, exactly as spec §2.1 (revised):
  - **Choose one partial form,** after validating every file's length:
    the `.bz2`, then pieces, then a legacy `.part`, then a fresh start.
  - **Run the pieces as tasks,** each through
    `stream_to_file(offset=start, expected_size=end-start, total_size=S,
    allow_whole_file=False)`.
  - **One watcher owns every network mode:** the pieces, the fallback
    single stream and the legacy single stream. Each runs as a task. The
    watcher is cancelled and awaited on every exit.
  - **Progress:** per-piece counters starting at the validated sizes; their
    sum goes to `_progress`.
  - **Stopping:**
    - stop the pieces by `task.cancel()` and await them all;
    - a watcher cancels them when the user's `_async_cancel` is set;
    - the user's cancel always wins.
  - **`RangeNotHonoured`:**
    - stop the siblings;
    - delete pieces 2–4 first;
    - then rename piece 1 to `.part` (or start it empty);
    - reset the speed samples;
    - run the single stream, unless cancelled.
  - **Assembly:**
    - copy pieces 1–4 in order into `.<compressed>.assembling.tmp`, inside
      `_in_thread`, checking `_thread_cancel` every 8 MiB in the copy and in
      the hash;
    - check the temporary file's SHA-256;
    - a match → rename to the `.bz2`, delete the pieces, unpack as today;
    - a mismatch → delete the temporary file and the pieces, then raise
      `ChecksumMismatch`.
- [ ] **`start_download` and `start_import`:** run `_clean_stale_staging()`
  after `_ensure_not_busy()` and before the free-space preflight.
  `already` is the size of the chosen form only.
- [ ] **`store.required_free_bytes`:** unchanged. The peak is S + U; spec
  §2.1 gives the reasoning. Add a test asserting the assembly fits within
  it.
- [ ] **`_clean_stale_staging`:**
  - keeps the `*.part*of4` files and still deletes hidden `*.tmp` files;
  - when a `.bz2` exists beside piece files or a `.part`, keeps the partials
    and deletes the `.bz2`. Size does not prove verification (spec §2.1,
    rounds 3–4).
- [ ] **Tests:** `tests/test_http_client.py` (the offset form, 206 exactness,
  `RangeNotHonoured`) and `tests/star_catalog/test_fetch.py` (spec §2.1
  list), with a fake that serves byte ranges from an in-memory body via
  `httpx.MockTransport`.
- [ ] **Docs:**
