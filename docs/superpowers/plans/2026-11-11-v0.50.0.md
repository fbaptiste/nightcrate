# v0.50.0 — XISF specification update: implementation plan

> **For agentic workers:** Codex implements one phase at a time under
> `docs/agent-collaboration.md` §4; Claude reviews each phase. Steps use
> checkbox (`- [ ]`) syntax. Never stage, commit or push.

**Goal:** NightCrate reads every XISF file a baseline decoder must read
under the revised specification (1.02, October 2026). That includes
PixInsight 1.9.6's compressed, checksummed files and solutions stored under
the `AstrometricSolution:` names, with the correct pixel origin. A damaged
file is refused with a plain message.

**Architecture:**
- A new module, `services/xisf_blocks.py`, reads any XISF data block:
  locate, verify the checksum, decompress subblocks, unshuffle. It owns the
  XISF error types.
- `services/xisf_io.py` uses it for pixels, property values and the stored
  solution. A new `read_solution` returns the WCS, or the reason there is
  none.
- `GET /plate-solve/detect-wcs` returns that pair. The Image Analyzer shows
  the reason, and shows pixel-load errors that it hides today.

**Tech stack:** Python 3.14, numpy, defusedxml, `hashlib`, `zlib`, `lz4`,
`zstandard`, Pydantic, FastAPI; React, TypeScript, TanStack Query. No new
dependency.

**Spec:** [v0.50.0 design](../specs/2026-11-11-v0.50.0-design.md), approved
by Fred on 2026-11-11 ("approved, go ahead with the plan"). Section numbers
(§) refer to the *XISF Version 1.0 Specification*, revision 2 (1.02),
<https://pixinsight.com/doc/docs/XISF-1.0-spec/XISF-1.0-spec.html>.

**Base:** `33ad668` on `v0.50.0/xisf-spec-update`.
- Codex works in the worktree `.superpowers/wt-v0.50.0`, detached at the
  base. Fred's `make dev` runs from the main checkout, and a backend edit
  there would reload it on his database.
- The spec and this plan are read from the main checkout.

**High-stakes** (`docs/agent-collaboration.md` §5):
- a migration (`uncataloged_file`, Task A7);
- backend–frontend contracts (`detect-wcs`, the scan status, the catalog
  summary, the new not-cataloged list);
- a scientific calculation that changes where every stored PixInsight
  solution lands: +0.5 px, and solutions found where none were before.

Both get a fresh independent review and real-file runs.

## Global constraints

- Clean-room: written from the published specification only. No GPL XISF
  library code, and no reading of other implementations
  (`docs/development-decisions.md`).
- XML parsing stays on `defusedxml.ElementTree`.
- Services raise domain errors, never `HTTPException`. Routers translate
  them.
- `XISFError` becomes a `ValueError` subclass, so the existing
  `except ValueError` → 422 handlers in `api/images.py` pass its message
  through. `api/images.py` itself is unchanged.
- Readers stay worker-safe and numpy-only. Thumbnails, frame quality and
  `pixel_loader` call them in spawned processes.
- One migration (`0072`, Task A7); no setting, no dependency. Never edit an
  existing migration.
- Existing callers keep their signatures:
  - `load_image_data(source, hdu=0)`;
  - `read_header(source, hdu=0)`;
  - `read_wcs_params(source, hdu=0)`;
  - `list_extensions(source)`;
  - `services/plate_solve.read_wcs_params(...)`.
- An unavailable block never makes the header unreadable (§7).
- A header read (`read_header`, `list_extensions`) never reads an attached
  block's bytes.
- **Supported scope** (Codex round 1). Don't claim more than this in code
  comments or docs.
  - Supported: §7.2's baseline decoder, plus the solution's layer 1 for
    gnomonic projections with default native coordinates.
  - Not supported:
    - distortion and projective layers;
    - other projections;
    - non-default native or celestial-pole coordinates;
    - distributed units;
    - colour management.
- **Every failure inside the reader** becomes an `XISFError` with a plain
  message. That covers codec errors (`zlib.error`, LZ4 and Zstandard
  errors), `struct.error`, XML `ParseError`, `UnicodeDecodeError` and
  `binascii.Error`. Nothing from the reader reaches a router as a 500.
- **Sizes are validated before reading or allocating:**
  - every size is a non-negative integer;
  - an attachment lies within the file;
  - the uncompressed size equals the expected size where one is known
    (W·H·C·item size for pixels; the element count × item size for
    properties).
- **Two compatibility extensions to the spec,** labelled as such in code
  comments:
  - an embedded block's `subblocks` and `checksum` are also accepted on the
    parent element (§10.6 places them on `Data`, the element with
    `compression`);
  - a `+sh` codec without its item-size field falls back to the sample
    size.
- **Checksum verification is on demand** (§10.5): a block is verified when
  its contents are loaded. Header reads don't load attached blocks, so they
  don't verify them.
- **Exception:** a scan also verifies each image's pixel-block checksum when
  it catalogs a file (Task A6), as the approved spec's "ingest refuses"
  requires.
- User-facing messages: Codex drafts the final wording in Task A5, and
  Claude checks it against the behaviour. The spec's meaning is fixed:
  - **Damaged file:** the file is damaged (its stored check doesn't match);
    re-save it from PixInsight or restore a backup.
  - **Unsupported data:** names what can't be read, such as the
    compression method or the data location. The rest of the file still
    reads.
  - **Unusable solution, one message per reason:**
    - another projection: name it; NightCrate shows gnomonic solutions
      only; solve the image here instead;
    - an unsupported solution version: name the version;
    - incomplete or malformed.

## Review focus

1. **A damaged attached property block in a good image.** For example, the
   checksum of `AstrometricSolution:ControlPoints:Image` fails while the
   pixels and the layer-1 properties are fine.
   - The image's pixels load, the header reads, and the solution reads.
   - Tests record every `seek`/`read` on the source and assert that no
     attached property block was touched.
   - Pinned in Tasks A2, A3 and A4.
2. **FITS WCS keywords beside an unusable new-style solution.** No solution
   and the reason are shown, never the keywords or the old names. Cases:
   Stereographic; version 2.0 with complete FITS and old-name solutions also
   present; an unusable new solution beside a usable old one. Pinned in
   Task A4.
3. **Files from other writers:** single-stream compression without
   `subblocks`, every codec, with or without shuffling, including `c == u`
   and `c > u`. They still open, with identical pixels.
   - Pinned in Task A1 with synthetic files.
   - On real files, Claude identifies compressed XISF from other writers on
     Fred's drive during the Phase C survey.
4. **A truncated or inconsistent file:** a truncated preamble or XML, an
   attachment past the end, subblock sizes that don't add up, malformed
   codec data without a checksum, trailing bytes, or two Zstandard frames
   in one subblock. Each gives an `XISFError`, and a 422 with a clear
   message at the HTTP boundary, never a 500 or a hang. Pinned in Tasks A1,
   A2 and A5.
5. **Large files:** Fred's 380 MB mono master.
   - Full `load_image_data`, normalisation included, in about 1 s or less.
   - Raw block decode measured separately.
   - Peak memory recorded.
   - Measured by Claude after Task A2 and in Phase C.

### Task A1: Data-block reader

**Files:**
- Create: `backend/src/nightcrate/services/xisf_blocks.py`
- Test: `backend/tests/test_xisf_blocks.py`

**Interfaces (produces):**
- Errors:
  - `class XISFError(ValueError)`;
  - `class XISFChecksumError(XISFError)`;
  - `class XISFUnavailableError(XISFError)`, for an unsupported codec,
    location or sample format.
  - Each message is user-facing.
- `@dataclass(frozen=True) class BlockSpec`, with these fields:
  - `location: str`, the raw attribute;
  - `compression: str | None`;
  - `subblocks: str | None`;
  - `checksum: str | None`;
  - `byte_order: Literal["little", "big"]`;
  - `encoded_text: str | None`, for inline or embedded blocks;
  - `encoding: Literal["base64", "hex"] | None`.
- `block_spec(elem: Element) -> BlockSpec`, built from an element that
  serializes a block:
  - for `location="embedded"`, the child `Data` (namespace-qualified)
    supplies `encoding`, `compression` and the text;
  - `subblocks` and `checksum` are read from `Data`, or from `elem` when
    `Data` lacks them (spec, Claude's call 10);
  - `byteOrder` comes from `elem`.
- `is_attached(spec: BlockSpec) -> bool`.
- `read_block(spec: BlockSpec, source: Path | BinaryIO | None, *,
  item_size: int | None = None, expected_size: int | None = None) -> bytes`.
  It returns the decoded, decompressed, unshuffled bytes, still in the
  block's byte order.
  - `source` is needed only for attachments.
  - `item_size` is the fallback when a `+sh` compression attribute omits
    its third field.
  - `expected_size` is checked against the uncompressed size before
    anything is allocated.
- `verify_block(spec: BlockSpec, source: Path | BinaryIO | None) -> None`
  checks the location, codec and checksum without decompressing. It raises
  as `read_block` would. Task A6 uses it.
- `unshuffle(data: bytes, item_size: int) -> bytes`. It returns `bytes`.
  It is a no-op for `item_size == 1`. A trailing partial item is kept
  unaltered (§10.6.3).

**Rules** (spec › Data blocks):
1. **Locate:**
   - `inline:base64` and `inline:hex`: ignore white space (§10.3). Accept
     either case of hex. Odd-length hex → `XISFError`.
   - `attachment:p:s`: read exactly `s` bytes at `p`. Short → `XISFError`.
   - Anything else (`url(...)`, `path(...)`, unknown) →
     `XISFUnavailableError`.
2. **Checksum** (§10.5, §10.6.2):
   - Format `algorithm:digest`.
   - Algorithms: `sha-1`, `sha1`, `sha-256`, `sha256`, `sha-512`,
     `sha512`, `sha3-256`, `sha3-512`, through `hashlib`. Compare digests
     case-insensitively.
   - The digest covers the bytes as stored: the decoded bytes for inline
     and embedded blocks, before decompression.
   - An unknown algorithm → `XISFUnavailableError`. A mismatch →
     `XISFChecksumError`. In both cases nothing is decompressed.
3. **Decompress** (§10.6, §10.6.1):
   - `compression` is `codec:uncompressed-size[:item-size]`.
   - Codecs: `zlib`, `lz4`, `lz4hc` (accept `lz4-hc`), `zstd`, each
     optionally `+sh`. Unknown → `XISFUnavailableError`.
   - Without `subblocks`: one subblock, compressed length = block length,
     uncompressed length = the attribute's size.
   - With `subblocks` `c1,u1:c2,u2:…`:
     - Σc must equal the block length.
     - `c == u` → copy unmodified.
     - Otherwise decompress, and the result must be exactly `u` bytes. The
       subblock's input must be fully consumed:
       - zlib through `zlib.decompressobj()`: `eof` set and `unused_data`
         empty;
       - Zstandard as exactly one frame per subblock (§10.6.10), through a
         decompression object: `eof` set and `unused_data` empty. A second
         frame or trailing bytes → `XISFError`;
       - LZ4 with `lz4.block.decompress(chunk, uncompressed_size=u)`. Probe
         how it treats trailing bytes and pin that behaviour with a test. If
         the block format can't detect them, say so in the report.
   - **Output is bounded while decompressing** (Codex round 2). No codec
     may produce more than `u` bytes plus a small fixed excess (at most one
     internal chunk) before the reader stops with `XISFError`. Comparing
     declared sizes isn't enough: a 20-byte Zstandard frame can expand to
     65,536 bytes. Use the codec's output limit, such as zlib's
     `max_length`, a bounded Zstandard stream read of `u + 1` bytes, or
     LZ4's `uncompressed_size`. Keep the complete-input checks.
   - The no-`subblocks` case follows the same rules (§10.6.1): `c == u` is
     copied, and `c > u` is decompressed.
   - Σu must equal the attribute's size, and the attribute's size must equal
     `expected_size` when the caller passes one.
   - Any violation, or any codec exception → `XISFError` ("invalid
     compressed block").
   - Remove `_is_single_stream` and the in-data size headers.
4. **Unshuffle** the whole concatenation for `+sh` codecs (§10.6.3).

- `_CANONICAL_TYPES: dict[str, str]`, mapping the spec's alternate names to
  canonical ones (§8.4.4.1–§8.4.4.6), for example `Vector` → `F64Vector`

  (`00-xisf-1.02-spec.txt`, the "Alternate name" columns) and list them in
  the report.
- `_extract_property_value` is removed. Its tests move to
  `_read_property` and `_display_value`.

**Rules** (spec › Properties):
- **Values:**
  - `value` attribute → `text` (scalars, Complex, TimePoint).
  - String without `location` → `text` = `prop.text` exactly, or "" when
    empty, with no decoding (§11.1.6).
  - String with a block → the block decoded as UTF-8. Invalid UTF-8 →
    unavailable.
- **Vectors and matrices:** the block decoded with dtype from the canonical
  type and the block's byte order. The element count must equal the length
  or rows × columns.
- **Display:**
  - up to 9 values → comma-separated numbers;
  - more than 9 → `"{type} {length}"` or `"{type} {rows}×{columns}"`;
  - attached → `"{type} {size} (stored in the file, not shown)"`;
  - unavailable → `"{type} (unavailable: {message})"`;
  - an unknown type → `"{type}"`.
- **`read_header`:**
  - calls `_read_property(prop, None)`, so it never reads attachments;
  - shows `_display_value` for unmapped properties;
  - maps a property into canonical keys (`OBJECT`, `FILTER`, `INSTRUME`,
    `EXPTIME`, …; `xisf_io.py` `prop_map`) only when `status == "ok"` and
    `text` is non-empty. A summary or unavailable text never becomes
    metadata.

### Task A4: Stored solutions

**Files:**
- Modify: `backend/src/nightcrate/services/xisf_io.py`,

**Rules** (spec › Stored plate solutions):

   - Present means any property id with that prefix.
