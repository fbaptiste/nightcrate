# v0.48.0 — Messier checklist and Planner project pills: implementation plan

> **For agentic workers:** Codex implements one phase at a time under
> `docs/agent-collaboration.md` §4; Claude reviews each phase. Steps use
> checkbox (`- [ ]`) syntax. Never stage, commit or push.

**Goal:** a Messier checklist page (110 slots filled by the user's own
project images, survey images crossed by an X otherwise) and a project pill
on Planner cards, as specified.

**Architecture:** one batched backend endpoint builds the 110 slots from a
pure service; the survey images come from the Planner's thumbnail service
through a new 4:3 variant (one cache migration); a second small endpoint
lists every project's main-target links for the Planner pill. The frontend
adds a persistent `/messier` page that reuses the Gallery's tile pieces
after they are generalised to a separate entry identity.

**Tech stack:** Python 3.14, FastAPI, Pydantic, aiosqlite, yoyo (backend);
React, TypeScript, MUI, TanStack Query, Zustand (frontend). No new
dependency.

**Spec:** [v0.48.0 design](../specs/2026-11-09-v0.48.0-design.md), approved
by Fred on 2026-11-09 ("approved, go ahead with the plan"), with the
mockup `.superpowers/mockups/v0.48.0/messier.html` (local) as the visual
reference. Fred authorised the whole version up to finalisation in one go,
including database changes, while he is away; Claude decides plan
questions and records them below.

**Base:** `6a04481` on `v0.48.0/messier-checklist`. Codex works in the
worktree `.superpowers/wt-v0.48.0` (Fred's `make dev` runs from the main
checkout, and any backend edit there would reload it on his database).

## Global constraints

- Main targets come only from `project_target`; retired means
  `project.active = 0` and counts nowhere.
- Imaging dates only from `project_session.session_date` through
  `services/gallery.valid_session_date`.
- Never edit an existing migration. The next one is `0071`.
- Services don't import `api/` or FastAPI. Routers own HTTP errors.
- No unbounded id lists in SQL (`IN` lists only over bounded sets, such
  as the 110 Messier objects or one page).
- Colours: teal `#00695c` / `#4db6ac` (light/dark) for the imaged check and
  map boxes; slate blue `#5b7a9e` / `#7d9ab8` for the pill; rig box
  `#ed6c02` 2 px with a 1 px `rgba(0,0,0,0.5)` outer edge; X lines white at
  45 % opacity, 1.5 px, `vector-effect: non-scaling-stroke`. Six-digit hex
  only. Values come from the mockup, not theme tokens.
- User-facing text, verbatim from the spec:
  - "Messier checklist"; "{n} of 110 imaged."; "{n} more have a project
    but no image yet."; "Of those not yet imaged, {n} never rise at
    {location}."
  - "Project, no image yet"; "No image yet"; "Sky survey"; "Scale
    unknown"; "Never rises at {location}"; "Not in your catalog data";
    "No project yet" (back of a tile only).
  - "Download OpenNGC in Admin › Catalogs to show the Messier checklist."
  - M 102 note: "NightCrate uses NGC 5866 for M 102. Its historical
    identity is disputed; some lists identify it with M 101."
  - "Open in Planner"; "Projects under images"; "Rig field"; "No rig";
    "Location"; "None"; "Field {w} × {h}, centred on each picture" (both
    in degrees with one decimal from 1° up, otherwise whole arcminutes).
  - Pill: one project → its name, hover "Open project: {name}"; several →
    "{n} projects ▾", hover "{n} projects have {designation} as a main
    target".
  - Planner status line: "Checking projects…" (after 500 ms, no data
    yet); "Couldn't check which objects have projects." (failure).

## Review focus

1. **One project in several slots** (an M 31 project listing M 32 and
   M 110): three tiles, three viewer entries, independent turning, focus
   return to the right tile. Pinned in Task B1 and the rendered checks.
2. **A stored setting pointing at a deleted rig or location:** falls back
   to No rig / the default location without an error. Pinned in Task A3.
3. **The Planner opened for the first time through "Open in Planner":**
   the saved detail panel must not overwrite the requested object. Pinned
   in Task C1.
4. **Survey servers down:** tiles fall back to blank and stop polling;
   nothing polls while the page is hidden. Pinned in Task B2.
5. **An own image whose main file isn't the solved file:** box only when
   the proportions match within 0.5 %; otherwise "Scale unknown". Pinned in
   Task A1.

  when `main_size_px` exists and its width/height ratio is within 0.5 % of
  the solve's (`abs(r_main / r_solve - 1) <= 0.005`); `None` otherwise or
  when the solve lacks a field.

- `survey_field_deg(maj_axis_arcmin: float | None) -> float` — delegates
  to `thumbnails.compute_angular_extent_deg("checklist", ...)` (Task A2),
  so there is one framing rule.
- `SlotState = Literal["imaged", "project", "none", "missing"]`.
- `slot_state(has_object: bool, ordered: list[Candidate]) -> SlotState` —
  `missing` without an object; `none` without candidates; `imaged` when
  the first has a main image; else `project`.

- **One canonical descriptor**, from which everything is derived:

```python
CHECKLIST_FRAMING_REVISION = 1

@dataclass(frozen=True, slots=True)
class ChecklistRender:
    ra_e4: int            # round(ra_deg * 10_000), as in today's file names
    dec_e4: int           # round(dec_deg * 10_000)
    field_mdeg: int       # round(field_width_deg * 1000)
    revision: int = CHECKLIST_FRAMING_REVISION
    width: int = 800
    height: int = 600

    @classmethod
    def for_object(cls, ra_deg: float, dec_deg: float, maj_axis_arcmin: float | None) -> "ChecklistRender": ...
    @property
    def render_key(self) -> str:   # "r1_ra{ra_e4}_dec{dec_e4}_f{field_mdeg}_800x600"
    @property
    def file_name(self) -> str:    # "ra{ra_e4}_dec{dec_e4}_checklist_800x600_{field_mdeg}_{revision}.jpg"
    @classmethod
    def from_file_name(cls, name: str) -> "ChecklistRender | None": ...
    def wcs(self) -> WCS:          # thumbnail_wcs(ra_e4/1e4, dec_e4/1e4, field_mdeg/1000, 800, 600)
```

  The render uses only the descriptor's quantised values, so the same
  descriptor always means the same picture. The database row, the file
  name, the startup reindex and the browser token are all derived from it
  (`render_key`). A future change to the framing rule bumps
  `CHECKLIST_FRAMING_REVISION`.
- `thumbnail_cache` gains a nullable `render_key TEXT` column (set only for
  `checklist`), and the unique index adds `COALESCE(render_key, '')`.
  `make_key(..., variant="checklist", maj_axis_arcmin=…)` builds a key
  carrying the descriptor; the lookup matches `render_key` for
  `checklist`. Other variants and their keys are unchanged.

```python
class MessierLocation(BaseModel): id: int; name: str; latitude_deg: float
class MessierRig(BaseModel): id: int; name: str; fov_major_deg: float | None; fov_minor_deg: float | None
class MessierObject(BaseModel):
    dso_id: int; designation: str; common_name: str | None; other_names: list[str]
    obj_type: str; constellation: str | None; mag_v: float | None
    maj_axis_arcmin: float | None; min_axis_arcmin: float | None; active: bool
class SlotProject(BaseModel):
    project_id: int; name: str; status: str; main_image_id: int | None
    crops: dict[CropSize, GalleryCrop]          # as the Gallery's, existing files only
    first_date: str | None; last_date: str | None; nights: int
    imaging_runs: list[ImagingRun]
    picture_fields: dict[CropSize, PictureField | None] | None   # projects with a main image only
class MessierSlot(BaseModel):
    number: int; object: MessierObject | None
    state: Literal["imaged", "project", "none", "missing"]
    never_rises: bool                            # False when imaged or no location
    projects: list[SlotProject]                  # candidates in slot order
    survey: SurveyImage | None                   # None when missing or no coordinates
class SurveyImage(BaseModel): field_deg: float; render_key: str   # field_mdeg / 1000, descriptor key
class MessierCounts(BaseModel): imaged: int; project: int; never_rises: int; missing: int
class MessierResponse(BaseModel):
    catalog_status: Literal["ready", "not_downloaded"]
    location: MessierLocation | None; rig: MessierRig | None
    counts: MessierCounts; slots: list[MessierSlot]; workspace_key: str
```

**Rules:**
- Objects: one query joining `dso_designation` (`catalog = 'messier'`) to
  `dso` with no `active` filter, keyed by `CAST(identifier AS INTEGER)`.
- `catalog_status = "not_downloaded"` only when no number resolves **and**
  neither `user_catalogs_root()/openngc/NGC.csv` nor `addendum.csv` exists.
  Then `slots` is empty and `counts` all zero.
- Candidates: `load_project_records` filtered to non-retired projects with
  a Messier object among targets, then `order_candidates(image_first=True)`.
- `picture_fields` for **every slot project with a main image** (the
  arrows can show any of them; amendment of 2026-11-09), per size,
  following what the tile shows (the Gallery's rule: a crop whose file
  exists, else the main image):
  - a crop whose source is the main image (`source_image_id` NULL or the
    main image's id) → `crop_field(main_field, crop_w, crop_h)`;
  - a crop from another image → `None`;
  - no crop, or its file missing → `main_field`;
  - `main_field` unknown → `None`.
  The loader reads, for the Messier candidate projects only (bounded): `project_solve` (path, size, field), the main image's
  `file_path`, and each crop's `source_image_id`, `crop_w`, `crop_h`.
  `main_field` comes from `main_image_field` with the main image's
  `thumb_lg.jpg` size read with Pillow (`Image.open(...).size`, no
  decode); a missing or unreadable file gives no size.
- `location`: `"none"` → `None`; an id that exists → it; anything else
  (`"default"`, a deleted id) → the `is_default = 1` location or `None`.
  Invalid text → 422.
- `rig_id`: a retired or missing rig → `rig = None` (no error); a rig
  without FOV data → `fov_* = None`.
- Counts: `never_rises` counts slots that aren't imaged.

```ts
// Tile = 4:3. Picture contained: Tw, Th are the tile's angular size.
const a = picture.widthDeg / picture.heightDeg;
const [Tw, Th] = a >= 4 / 3
  ? [picture.widthDeg, picture.widthDeg * 0.75]
  : [picture.heightDeg * (4 / 3), picture.heightDeg];
const scale = Math.max(1, rig.majorDeg / (Tw * 0.92), rig.minorDeg / (Th * 0.92));
return { scale, boxWidthPct: (rig.majorDeg / (Tw * scale)) * 100,
         boxHeightPct: (rig.minorDeg / (Th * scale)) * 100 };
```
